# atsu.moe (Atsumaru) source spec for MangaCracker

Tested 2026-11-01 with plain GET requests (no login, no cookies, ~1 req/s). Every endpoint below returned the sample
shown. Probe scripts: `_dev_tools\probe_atsu\` (`probe.py NAME URL ...`, `probe_home2.py`, `run_search*.py`,
`probe_images.py`, `probe_cf.py`). Saved raw responses: `_dev_tools\probe_atsu\out\*.json`. The site's JS bundle is
saved in `probe_atsu\bundle\`. Search params and image rules come from `toSearchItem-*.js`, `staticImages-*.js`,
`constants-*.js` and `enums-*.js`.
Full genre and tag list with ids: `_dev_tools\specs\atsu_tags.tsv` (6,174 rows, generated by
`probe_atsu\make_tags_tsv.py`).

Cross-check: keiyoushi/extensions-source has `src/en/atsumaru` (Atsumaru.kt / Dto.kt / Filters.kt, versionCode 25,
last commit 2026-10-31). Copies are in `probe_atsu\keiyoushi\`. Its endpoints match this spec. Section 9 lists the
differences.

## 0. Basics

| what | value |
|---|---|
| Site / API base | `https://atsu.moe` |
| JSON API | `https://atsu.moe/api/<group>/<name>?...` (a Hono client: `K.manga.page.$get` maps to `/api/manga/page`) |
| Search engine | Typesense, proxied at `https://atsu.moe/collections/manga/documents/search?...` (no API key needed; `access-control-allow-origin: *`) |
| Image CDN | `https://cdn.atsu.moe/static/<path>` |
| Manga web URL | `https://atsu.moe/manga/<mangaId>` |
| Chapter web URL | `https://atsu.moe/read/<mangaId>/<chapterId>` |
| Author web URL | `https://atsu.moe/browse/author/<slug>?type=Author` |
| IDs | short strings, case-sensitive, can contain `-` / `_` (`ZrRJ`, `sVC2A`, `sL-c`, `86_W`). Chapter ids are similar (`XYDXv2`, `-3yV8O`) |

**Headers:** none are required. Every API, Typesense and CDN call returned 200 with the python-requests default UA,
with `User-Agent: okhttp/4.12.0`, with no `Accept`, no `Referer` and no cookies. Recommended:
`User-Agent: <your app UA>`, `Accept: application/json` (API) / `Accept: image/avif,image/webp,*/*` (images).
keiyoushi adds `Accept: */*` and `Content-Type: application/json` to every call. Neither header is needed.

**Timestamps:** epoch milliseconds (Long) everywhere, except `/api/manga/chapters`, which gives ISO-8601 strings.
**Views:** API rows give `views` as a formatted string (`"8.1M"`, `"48"`). Typesense gives `views` as a Long and
`popularity` as the formatted string.

**Enums** (from `enums-*.js` / `/api/explore/availableFilters`)
- `type`: `Manga`, `Manwha` (note the spelling; display it as "Manhwa"), `Manhua`, `OEL`, `Other`
- `medium`: `Comic`, `Novel`. Filter `Novel` out: the site also hosts light novels, which have no page images.
- `status`: `Ongoing`, `Completed`, `Hiatus`, `Canceled`
- `mbContentRating` (Typesense only): `Safe`, `Suggestive`, `Erotica`, `Pornographic`
- author `type`: `Author`, `Artist` (`Unknown` also exists in the enum)

### Image URL rule (covers, banners, pages)
The JS (`staticImages.js`) does this:
```
CDN = "https://cdn.atsu.moe"
fun rel(p) = p.removePrefix("$CDN/static/").let { if (it.startsWith("/static/")) it.drop(8) else it }
fun imageUrl(p): String = when {
    p.startsWith("http")  -> p          // already absolute (not seen, but handled by JS + keiyoushi)
    p.startsWith("//")    -> "https:$p"
    else                  -> "$CDN/static/${rel(p)}"
}
```
Forms seen: `posters/X.jpg` (API rows), `/static/posters/X.jpg` (Typesense), `/static/pages/<chapterId>/0.webp` and
`/static/pages/<mangaId>/<chapterId>/0.webp` (pages; both forms occur, so always use the given path, never build
it yourself), `banners/ZrRJ.jpg`.

**AVIF to WebP:** each `*.avif` cover has a `.webp` twin at the same path (tested: `-small.webp` gives 200 image/webp).
The site swaps `.avif` for `.webp` when the browser can't decode AVIF. On Android, AVIF decodes natively from API 31
(Coil / ImageDecoder). Below that, request the `.webp` twin.

## 1. Browse rows: Popular, Trending, Latest, Recommended

### 1a. Home rows `/api/home2/<row>` (offset paging)
```
GET https://atsu.moe/api/home2/popular?offset=0&limit=40&timeframe=daily&types=Manga,Manwha,Manhua,OEL&mediums=Comic
```
Query params (all optional; built by `o()` / `s()` in toSearchItem.js):

| param | meaning |
|---|---|
| `offset`, `limit` | paging. The site uses limit 40. `limit=100` worked. No total is returned, so `hasNext = items.size == limit` |
| `timeframe` | `daily` / `weekly` / `monthly` / `all`. Used by `popular`, `mostBookmarked` and `mostTalkedAbout` |
| `types` | comma list of `type` values |
| `mediums` | `Comic` (always send it, to drop novels) |
| `includedTags` | comma list of genre and/or tag ids. **OR** semantics: tested `39,36` returned rows with 39 or 36, not both. Not honoured by `recentlyUpdated` (`supportsIncludeTags:false`) |
| `excludedTags` | comma list of genre and/or tag ids, none of which may appear (tested) |
| `contentRatings` | comma list of `Safe,Suggestive,Erotica,Pornographic` |
| `adult` | `1` = **adult mode: ONLY isAdult titles** (tested: 20/20 adult). Leave it out for safe mode (tested: 0/20 adult) |

Response (every row): `{"items":[MangaRow...]}`
```json
{"items":[{"id":"0OElQ","title":"Blue Lock",
  "image":"posters/PpYZrYu1LUs0GVYT.jpg","smallImage":"posters/PpYZrYu1LUs0GVYT-small.avif",
  "mediumImage":"posters/PpYZrYu1LUs0GVYT-medium.avif","largeImage":"posters/PpYZrYu1LUs0GVYT-large.avif",
  "isAdult":false,"type":"Manga","medium":"Comic","mbRating":8.24357142857143,"views":"8.1M",
  "createdAt":1752295945579,"updatedAt":1793389670151}]}
```
`MangaRow` = `id, title, image, smallImage, mediumImage, largeImage, isAdult, type, medium, mbRating?, views,
createdAt?, updatedAt?` (`recentlyUpdated` has no `createdAt` or `mbRating` on some rows; treat all but id/title as nullable).

Rows tested without login (all 200, safe, same shape):

| UI name | path | notes |
|---|---|---|
| **Popular** | `popular` | `timeframe` daily (site default) / weekly / monthly / all |
| **Latest updates** | `recentlyUpdated` | newest chapter uploads first (`updatedAt`) |
| Recently added | `recentlyAdded` | new series |
| Top rated | `topRated` | |
| Hot updates | `hotUpdates` | |
| Rising | `rising` | |
| Hot arrivals | `hotArrivals` | |
| Most bookmarked | `mostBookmarked` | `timeframe` (site default weekly) |
| Most talked about | `mostTalkedAbout` | `timeframe` (site default weekly) |
| Binge-worthy | `bingeWorthy` | |
| Hidden gems | `hiddenGems` | good "Recommended" without login |
| Most polarizing | `mostPolarizing` | |
| Genre spotlight | `genreSpotlight?genre=Action&offset&limit` | `genre` = genre NAME |
| (login only) | `recommended`, `forYou` (`{"rails":[]}`), `updates`, `bookmarks` | return empty lists without login |

`/api/search/popular` (no params) gives `{"items":[20 MangaRow]}`, the "popular searches" list. It is unfiltered, so
check `isAdult` yourself.

### 1b. Trending
There is no home2 "trending" row. The site's "Trending" sort is Typesense `sort_by=trending:desc`
(section 2), for example:
```
.../collections/manga/documents/search?q=*&query_by=title&filter_by=isAdult:=false && hidden:!=true&sort_by=trending:desc&page=1&per_page=40&include_fields=...
```

### 1c. Recommended / related for one manga
- `mangaPage.recommendations[]` and `mangaPage.similarManga[]` (20) are both in the details call (section 4), as `MangaRow` without dates.
  keiyoushi's "related manga" = `recommendations`.
- More, paged (page is 0-based, 40 per page; tested page 0 = 40 and page 1 = 8, then empty):
  `GET /api/infinite/mangaSimilar?mangaId=ZrRJ&page=0&types=Manga,Manwha,Manhua[&adult=1][&includeAdult=1]`
  `GET /api/infinite/mangaRecommendations?mangaId=ZrRJ&page=0[&adult=1][&includeAdult=1]`
  Both return `{"items":[MangaRow...]}`. `includeAdult=1` = safe plus adult mixed (the site sends it when the user allows Pornographic).
- `mangaPage.relations[]` = `[{"type":"SpinOff","manga":MangaRow}]` (sequels, spin-offs and so on).

## 2. Search (Typesense)

```
GET https://atsu.moe/collections/manga/documents/search?<params>
```
Params exactly as the site builds them (`U()` in toSearchItem.js):

| param | value |
|---|---|
| `q` | search text, or `*` for browse |
| `query_by` | `title,englishTitle,otherNames,authors,acronyms` |
| `query_by_weights` | `4,3,2,2,1` |
| `num_typos` | `4,3,2,1,0` |
| `prefix` | `true,true,true,true,false` |
| `infix` | `off,off,fallback,off,off`, only when `q` is not `*` |
| `include_fields` | `id,title,englishTitle,authors,poster,posterSmall,posterMedium,type,medium,isAdult,status,year,mbRating,popularity,dateAdded` (leave it out to get the full document: genreIds, tagIds, synopsis, chapterCount ...) |
| `filter_by` | clauses joined with ` && ` (see below), and **always** `hidden:!=true` |
| `sort_by` | the site sends it only when `q=*`. With text, relevance is the default, but `sort_by` also works with text (tested `q=dragon&sort_by=views:desc`) |
| `page` | **1-based** |
| `per_page` | the site uses 40. **250 works** (Typesense max) |

### filter_by clauses (values wrapped in backticks; escape a backtick in a value as `` \` ``)
| want | clause |
|---|---|
| include genre A **and** B | ``genreIds:=`39` && genreIds:=`36` `` (one clause per id = AND) |
| include genre A **or** B | ``genreIds:=[`39`,`36`]`` |
| exclude genres | ``genreIds:!=[`9`,`6`]`` |
| include tags (AND) | ``tagIds:=`248` && tagIds:=`337` `` |
| exclude tags | ``tagIds:!=[`28`,`35`,`1769`,`1770`]`` |
| type | ``type:=[`Manwha`,`Manhua`]`` |
| status | ``status:=[`Completed`,`Ongoing`]`` |
| medium (no novels) | ``medium:!=[`Novel`]`` (or ``medium:=[`Comic`]``) |
| year | `releaseYear:=[2018,2019]` |
| chapter count | `chapterCount:>=50`, `chapterCount:<=200` |
| official English translation | `officialTranslation:=true` |
| author (exact Typesense name) | ``authors:=[`ODA Eiichiro`]`` (tested: 6 hits). See section 3 for the name gotcha |
| safe mode (site default) | `isAdult:=false`, and when `q=*` also ``mbContentRating:!=[`Pornographic`]`` |
| safe + "show adult" | no isAdult clause |
| adult mode | `isAdult:=true` |
| with sort `views:desc` | the site adds `views:>0`. With sort `mbRating:desc` it adds `mbRating:>0` |

Tested: `isAdult:=false && genreIds:=`39` && genreIds:=`36` && genreIds:!=[`9`,`6`] && tagIds:!=[`28`,`35`,`1769`,`1770`] && type:=[`Manwha`,`Manhua`] && status:=[`Completed`]`
gave found 606, and all 10 checked hits matched every clause. A bad field gives HTTP 400
`{"message":"Could not find a filter field named `x` in the schema."}`.

### Sort options (`sort_by`, all tested)
| UI | sort_by |
|---|---|
| Popularity (default) | `views:desc` (+ filter `views:>0`) |
| Trending | `trending:desc` |
| Recently added | `dateAdded:desc` |
| Release date | `releaseDate:desc` (`released:desc` is identical; keiyoushi uses `released`) |
| Top rated | `mbRating:desc` (+ filter `mbRating:>0`) |
| Title | `title:asc` |
| Most chapters | `chapterCount:desc` (works; not in the site's UI) |
| Relevance | leave out `sort_by` (with text) |
| Random | `_eval(shuffleA:>=SEED):desc,shuffleA:asc,shuffleB:asc` (SEED 1..2147483646; the site's function `p()`) |
Any field can take `:asc`. The site's other sorts (hotUpdates, rising, mostBookmarked ...) are not Typesense
sorts. They use the home2 rows in section 1a.

### Response
```json
{"facet_counts":[],"found":611,"out_of":28501,"page":1,
 "request_params":{"collection_name":"manga","first_q":"*","per_page":3,"q":"*"},
 "search_cutoff":false,"search_time_ms":8,
 "hits":[{"document":{"authors":["GEE So-Lyung","JANG Sung-Lak","Redice Studio"],"dateAdded":1751846327307,
   "id":"oZOG5","isAdult":false,"mbRating":8.61666666666667,"medium":"Comic","popularity":"3M",
   "poster":"/static/posters/cGoOe70KFmmEBe4m.jpg","posterMedium":"/static/posters/cGoOe70KFmmEBe4m-medium.avif",
   "posterSmall":"/static/posters/cGoOe70KFmmEBe4m-small.avif","status":"Completed","title":"Solo Leveling",
   "type":"Manwha","year":2018},

```
Paging: `hasNext = page * request_params.per_page < found`. With text there are also `text_match`, `text_match_info` and `highlight(s)`
(ignore them).
Full document fields (without `include_fields`): `id, title, englishTitle?, otherNames[], acronyms[], authors[]
(names), synopsis, genreIds[], genreWeightKeys[], tagIds[], tagWeightKeys[], tags[] (= genre NAMES), type, medium,
status, isAdult, hidden, mbContentRating, mbRating, views (Long), popularity (String), trending (Int), chapterCount,
dateAdded, released, releaseDate, releaseYear, year, officialTranslation, poster, posterMedium, posterSmall,
shuffleA, shuffleB, weebCentralId?`.
Typesense has no `largeImage`. Use `poster` (the original jpg) for the best quality.

Also present but not recommended: `/api/search/manga?<same params>` (the site uses it only for signed-in "prefs" /
hideBookmarked). It returns `{"hits":[...]}` with no `found` / `page`.

## 3. Author / artist works

From a manga, `mangaPage.authors[]` = `{"id","name","slug","type":"Author"|"Artist"}` (the same person can appear
once per role). Then:
```
GET https://atsu.moe/api/browse/author?authorSlug=jirou-taniguchi&type=Author&page=0
{"author":{"name":"Jirou Taniguchi"},
 "items":[{"id":"86_W","title":"The Quest for the Missing Girl","image":"posters/oXUioBq5L5Jlir6D.jpg",
   "smallImage":"...-small.avif","mediumImage":"...-medium.avif","largeImage":"...-large.avif",
   "isAdult":false,"type":"Manga","medium":"Comic","mbRating":7.24,"views":"48"}, ...]}
```
- `type` is optional: leave it out for all roles (Taniguchi: 5 with no type, 4 as Author). Oda: 13 with no type, 8 as Artist.
- `page` is 0-based. Page 1 for Oda was `items:[]`, so keep paging until `items` is empty (page size not confirmed; ≥13).
- Unknown slug gives 200 `{"author":null,"items":[]}`.
- There is no free-text author search endpoint for anonymous users (`/api/user/search` is for users, not authors). Search text
  does match author names, because `authors` is in `query_by`.
- **Gotcha:** Typesense `authors[]` holds a different spelling (`"ODA Eiichiro"`) from `mangaPage.authors[].name`
  (`"Eiichirou Oda"`, slug `eiichirou-oda`). So use the slug endpoint for "more by this author". Use the Typesense
  `authors:=[...]` filter only with names taken from a Typesense document.

  shows it as a vertical strip.

## 5. Full chapter list

```
GET https://atsu.moe/api/manga/allChapters?mangaId=ZrRJ
{"chapters":[
 {"id":"XYDXv2","scanlationMangaId":"cmkrk7fnd00010vp9xcn9zrip","title":"Chapter 47","number":47,
  "createdAt":1769214112996,"index":31,"pageCount":23,"progress":null},
 {"id":"VetRgs","scanlationMangaId":"cmkrk7fnd00010vp9xcn9zrip","title":"Chapter 45","number":45,
  "createdAt":1769214104712,"index":30,"pageCount":24,"progress":null}, "..."]}
```
- **No paging.** It returns everything in one call (ONE PIECE: 1,198 chapters, 204 KB, 0.04 s).
- Includes **every group's uploads**, so the same `number` can appear once per scanlator (ONE PIECE: Alpha 1197 + TCB 1).
  Order = grouped by scanlator, each newest first (`index` desc), so **sort it yourself** (keiyoushi: number desc,
  then scanlator, then date desc). Optional dedup: per `number`, keep the group with the highest `scanlators[].score`.
- `number` is a JSON number (use Float/Double; decimals possible). `title` is always set ("Chapter 47" or
  "Chapter 1: The Undefeated Summit"). `createdAt` = epoch ms. `pageCount` int. `progress` is null without login.
- Scanlator name: join `scanlationMangaId` with `mangaPage.scanlators[]` (from `/api/manga/page`). Run both calls in
  parallel, as keiyoushi does.
- Alternative (not needed): `GET /api/manga/chapters?id=<mangaId>&page=0` (0-based, 50 per page, `{"chapters":[{id,title,
  number,index,pageCount,createdAt:"ISO string"}],"pages":24,"page":0}`). It lists only ONE scanlator's chapters
  (ZrRJ: 15 of 47), and `sort=asc` gives an odd order. Avoid it.

```
           "aspectRatio":0.7227891156462585,"spreadStart":false}, "... 23"]}}
```
- Image URL = rule above, for example `https://cdn.atsu.moe/static/pages/XYDXv2/0.webp`. Keep the `pages` order (`number`
  is 0-based).
- `width` / `height` are given for every page (use them for placeholders). Manhwa example (Solo Leveling ch 200): 49 pages,
  all 720×4000, path form `/static/pages/oZOG5/PwTgD1Gh/0.webp`. Pages seen are all `.webp`.
- `spreadStart:true` marks the left page of a double-page spread.
- Unknown chapter gives **404** `text/plain` "Chapter not found".
- **Image requests need no headers.** Tested 2 pages: no Referer + python UA gave 200, and foreign Referer
  (`https://example.com/`) + custom UA gave 200. Both were `image/webp`, `cache-control: public, max-age=31536000, immutable`,
  `cf-cache-status: HIT`, no cookies. Covers behave the same.

## 7. Adult / safe, rate limits, Cloudflare

**Safe vs adult** (from the site's code + tests):
| mode | home2 rows / similar / recs | Typesense |
|---|---|---|
| Safe (default) | leave out `adult` (0/20 adult tested) | `isAdult:=false` (+ ``mbContentRating:!=[`Pornographic`]`` when `q=*`) |
| Safe + adult allowed | `contentRatings=Safe,Suggestive,Erotica,Pornographic` (mixed: 3/20 adult); similar/recs: `includeAdult=1` | no isAdult clause |
| Adult only | `adult=1` (20/20 adult) | `isAdult:=true` |

`isAdult` is on every row and document, so filter on the client too. `/api/search/popular`, `relations`,
`recommendations` / `similarManga` inside `mangaPage` and `browse/author` take no mode param (the site filters
`search/popular` on the client; the others were not tested with adult titles). Drop `isAdult` rows yourself in safe mode. The hide-by-default tag ids (section 2) apply in every mode.

**Rate limits:** no rate-limit headers (`x-ratelimit-*`, `retry-after`) on any response, and no 429 seen at ~1 req/s
(about 60 requests in total). Bursts were not tested (probe rule). keiyoushi uses `rateLimit(2)` (2 req/s). Use ≤2 req/s for API
calls. Images come from Cloudflare cache (HIT) and are not limited in practice, but keep a sane concurrency (4-6).
The site's JS only shows 429 messages for uploads / messages, not for reading.

**Cloudflare:** everything sits behind Cloudflare (`server: cloudflare`, `cf-ray`). With no cookies and a plain
UA (python-requests, `okhttp/4.12.0`), every API, Typesense, CDN and even HTML page (`/manga/ZrRJ`) gave 200,
`cf-mitigated` absent, no challenge page, no `Set-Cookie`. No WebView or cookie handling needed (today). Still,
detect HTML / 403 / 503 responses on API calls and show a "Cloudflare" error.

## 9. keiyoushi Atsumaru differences (for awareness)

| item | keiyoushi | this spec / site |
|---|---|---|
| Popular | `/api/home2/popular?offset&limit=40&types=Manga,Manwha,Manhua,OEL&mediums=Comic&timeframe=daily[&adult=1][&excludedTags=..]` | same |
| Latest | `/api/home2/recentlyUpdated?...` | same |
| Search | Typesense, `query_by=title,englishTitle,otherNames,authors`, `num_typos=4,3,2,1`, always adds ``(mbContentRating:=[`Safe`,`Suggestive`,`Erotica`] || mbContentRating:!=*)``, ``medium:!=[`Novel`]``, `views:>0`, `per_page=40` | site also searches `acronyms` and uses `infix` for text. Note keiyoushi's `views:>0` drops unviewed series |
| Release sort | `released:desc` | site `releaseDate:desc` (both work, same result) |
| Details | `/api/manga/page?id=`; cover = `largeImage` (400×600 avif) | `poster.image` original jpg is sharper (820×1200) |
| Chapters | `/api/manga/allChapters?mangaId=` + scanlator names from mangaPage; optional dedup by score; scanlator blacklist | same |

| Related | `mangaPage.recommendations` | also `similarManga`, `/api/infinite/mangaSimilar` |
| Filters | from `/api/explore/availableFilters`; tags grouped A-Z | same endpoint |
